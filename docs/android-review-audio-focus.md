# Mobile Review set audio focus

Android and iOS Review set speech requests transient, may-duck audio focus for the complete playback scope instead of only while an individual recording or synthesized phrase is audible. A standalone session owns focus while it is running with speech enabled and has cards. An Interval session owns focus while it is running, Review playback has not been manually paused, the current step has **Play Review set during this step** enabled, and the Review snapshot has cards. The short playback pauses at the beginning and end of an eligible Interval step do not release focus. Entering a step where Review playback is disabled stops any utterance carried from the preceding step before releasing focus, allowing other audio to return to full volume immediately.

Audio focus is enabled by default. Native standalone and dense Interval Review action menus include a checked **Audio focus** option with a subtitle explaining that it lowers the volume of other apps during Review playback. Clearing it releases the current focus lease immediately and prevents both foreground and Android background Review playback from requesting it; Review speech continues without ducking other audio. The preference is stored locally and shared by both Review runners.

While the Android interval service is running, it is the sole owner of that interval's audio focus, including while the app is visible. The web runner relinquishes its duplicate lease after the service starts and cannot reacquire it through visibility changes or reactive updates. This lets the native timer release focus on a step without Review playback even when the WebView is suspended. Standalone Review scopes remain independent, and foreground interval focus remains available when native background timing is unavailable. Stopwatch and confirmation steps do not hold Review focus.

Minimizing BackOnTrack or turning off the phone screen does not release an active playback scope, including when a device without native background playback temporarily marks the standalone Review as visibility-paused. When the app becomes active again, both the shared web policy and the native lifecycle check whether an existing scope still needs focus and reapply it if the operating system removed it. Manually pausing or ending a standalone Review, pausing or ending its parent Interval, manually pausing Interval Review playback, or moving to a step without Review playback releases the scope. Android background playback services participate in the same shared lease so foreground/background handoffs and overlapping native sounds cannot restore other media prematurely. iOS uses a spoken-audio playback session with ducking and notifies other audio sessions only when Review playback actually releases its scope.

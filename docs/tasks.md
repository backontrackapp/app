# Tasks

Opening the Tasks view selects the current day. Choosing another date remains in effect while working in that view, but returning to Tasks starts from today again.

When available, **Done** and **Undone** appear after the other main task actions, above the divider and the Edit/Duplicate actions.

Task menus offer **Done** while incomplete or **Undone** while complete, except when the menu includes **Lock in numbers** or **Unlock numbers**. This applies to both full task menus and Quick log. These completion actions update the selected day's occurrence immediately, even when it must first be created offline. Done records manual completion; Undone clears it and preserves logged amounts, journal entries, session history, and individual program requirements. An explicit undone marker in the occurrence's completion state prevents existing values or completed requirements from immediately completing the task again after refresh. Future dates and locked program steps retain their action restrictions.

The task editor does not expose the former optional **Why does this matter?** description field. Existing stored descriptions remain intact when another task setting is edited.

Tasks support an optional emoji icon selected from the searchable, full-screen virtual list above the color picker. The selector keeps its header, search, and results clear of native safe areas. Active, incomplete task and program-step cards use the selected task icon first, then an attached interval or Review set icon, and finally the task-type icon. Individual interval requirements use their attached interval icon. The task editor's attached-interval selector shows each saved interval's icon and color directly in its menu and selected value. Completed, historically skipped, locked, archived, and syncing cards retain their state indicators.

Swiping left across the Tasks view advances to the next date, while swiping right returns to the previous date. Date-dependent content moves in from the navigation direction with a quick horizontal transition, a centered card briefly confirms the newly selected date before fading away, and the Quick log row resets to its left edge. The week selector and horizontally scrollable Quick log row keep their own swipe behavior. A vertical mouse wheel over Quick log scrolls that row horizontally, while native horizontal trackpad scrolling remains unchanged.

The task editor's archive action offers a choice between archiving and permanent deletion. Archiving removes a task from its schedule and reminders while preserving its settings, entries, and history. Archived tasks appear in the collapsible Archive section below Not scheduled, where selecting one opens the editor so it can be restored. Permanent deletion removes the task, its program steps, occurrences, entries, and image logs; saved interval and Review sessions remain in history without task attribution.

Time-based tasks can have more than one scheduled time. The task editor adds another time wheel for each additional instance and allows any extra instance to be removed while keeping at least one time. On the Tasks timeline, every configured time displays an independent task instance, and completing one instance updates only that scheduled time. Existing dated progress is assigned to the task's first configured time when this behavior is introduced. Quick log shows only instances from the task's current schedule, so dated progress retained under an earlier time does not create a duplicate shortcut after the schedule changes.

Archived tasks remain visible in recent task history without an archive tag.

The task action menu includes **Edit** and **Duplicate**. Duplicate opens a new task prefilled with the original task's settings. The copy receives an independent name, ordering, and program steps, and is not created until the editor is saved. The Tasks view does not offer Log history or its entry editing and deletion controls. Existing logs are preserved, and amount logging still supports Add, Subtract, and Set.

Task skipping and pausing are no longer offered. Task menus have no Skip, Unskip, Pause, or Unpause actions, and task management shows one list without a Paused tab. Use the editor's Archive action to remove a task from its schedule while retaining its history. Previously paused tasks are moved to Archive; restoring one makes it active again. The same interpretation applies immediately to older offline snapshots, and archive/restore updates are optimistic. Existing skipped occurrences remain readable in dated history and retain their original completion-score treatment. Legacy occurrence handling remains compatible with previously saved and queued data. Timer, Interval, and Review set pause controls are separate and remain available.

New program-step requirements default to the **Workout** completion style. The exercise selector appears directly below that style only for workouts, and an optional attached Interval starts from the primary workout action before the workout is confirmed. Exercise ids remain stable when a step or task is duplicated. The Exercise setting controls whether workout set weights default to kilograms or pounds; individual `ExerciseSetEditor` instances can override that default through their `unit` prop. Workout confirmations use an inviting empty alert as the complete empty-state container—title, helper copy, invitation, and full-width **Add set** action—until entries exist, then show a compact inline Rep/Weight table with a per-row remove action. Each edit saves the complete set list immediately against the active program-step completion and date. That dated log keeps historical workouts accurate, while the same latest set list becomes the default whenever that program-step/exercise relationship is opened again. When a workout has an attached Interval, its set list is fixed to the total expanded number of **Train** intervals, including nested repetitions; users can adjust only the Rep and Weight values. Rep and weight values open the same tap-first number pad used for amount logging. Starting a program opens an immersive screen with the program title centered and every requirement displayed in the same shared list used by task cards. A translucent **Next** action at the bottom opens the next unfinished requirement; Interval and Review-set requirements open their runner start screens directly. Selecting an unfinished workout or exercise requirement on its Tasks card skips the program overview and opens that focused exercise screen directly; selecting any other unfinished requirement likewise opens its focused completion flow. A first Interval requirement without an exercise opens that Interval’s start screen immediately. Back, Leave, and start-screen Cancel navigation in programs, Intervals, and Review sets always returns to the Tasks home screen. Otherwise, workouts use the shared workout-exercise panel in both the program screen and active Interval runner. Its default **Repetitions** tab contains the rep/weight editor, while **Exercise details** contains the demonstration media and guidance. An attached Interval starts first and returns to its workout confirmation after completion. Every workout, check-off, or quantity confirmation uses one **Confirm and finish** action instead of a two-button footer. **Done** on a completed Interval or Review-set runner opens the next unfinished program requirement directly; when none remains, it opens the program completion screen. The program header keeps the centered title between a left-side minimize control and a right-side overflow control; ending from the overflow menu keeps completed requirements and leaves unfinished work incomplete. Once a dated program occurrence exists, its task menu labels the runner action **Continue program** instead of **Start program** and opens the next unfinished requirement directly, including its Interval or Review-set runner. Editing a program from one of its dated task cards opens that card's program-day step, waits for the task form to render, and then scrolls smoothly until the expanded panel's top edge sits directly below the app bar. Program steps can be duplicated from their expanded editor; the copy is inserted on the following program day with independent completion requirements and opens immediately for editing. Check-off, Interval, and Review set requirements can also have an optional label that identifies the requirement on its task card.

Removing a program step checks its complete occurrence, entry, Interval-session, and Review-session history. A step with any historical reference is archived so its definition and log links remain intact, and its removal action is labeled **Archive step**. A step with no references is permanently deleted and labels the action **Delete step**. Remaining steps close the removed day in the program sequence.

Changing the completion requirements of a program step with history versions the step when the program is saved. The previous step becomes inactive and keeps its original completion styles for existing occurrences, entries, Interval sessions, and Review sessions, while a new active step uses the edited requirements for future progress. Editing only the step name or description does not create a new version.

On mobile, the next incomplete task banner appears only when no incomplete task card is visible between the app bar and bottom navigation. It links to the nearest incomplete task farther down the page.

Number trackers with a target can be attached to a scheduled Tracking task. Their task card keeps the numeric goal presentation and amount logging, but the target, unit, goal operator, tracking window, and values come from the tracker. When a log exactly fills the positive amount remaining to its target, the Tasks view asks whether to lock in the total. Locking finishes the task and prevents more changes for that day; skipping leaves it unlocked so more values can still be logged.

Daily Total tasks can optionally enable **Log with images** to quickly log a reusable labeled amount from a photo. Other task types use their standard amount, timer, session, sync, or completion controls and do not expose image logging.

Duration trackers with a target use the same task-card progress, amount logging, timer, and **Lock in total** actions. Their **Log amount** action opens the number pad directly, matching number trackers, and converts the selected minutes or hours to stored seconds. Locking finishes the task for that day and prevents further timer or amount changes while preserving the day's logged duration and earned progress; the same menu can unlock the total again.

Logged amounts update task progress immediately. Background persistence and synchronization refreshes preserve that optimistic value so totals do not temporarily revert while the save is in flight.

Tasks with a manually logged numeric or duration target always offer **Lock in numbers** while unlocked, in both the full task menu and Quick log. The action is available even with no entries or before reaching the target, and opens the lock-in confirmation. When a Tracking task's numbers are locked in, its Quick log menu replaces **Log entry** with **Unlock numbers**. Selecting it unlocks that day's total immediately through the existing offline-first update, preserving logged values and making **Log entry** and **Lock in numbers** available again. Locking and unlocking remain available when the attached tracker is paused. Automatic Health Connect step totals do not support locking.

Amount logging always uses the shared number pad on mobile and desktop, including standard task logs, program quantity requirements, and reusable image-log amounts. These logging flows never open a native number field.

Synchronization silently discards rejected changes for task-log, Tracking, and Journal entries when their entry no longer exists on the server, as well as task-log entries rejected for having a zero value. These states cannot succeed on retry: missing entries are already absent, while removing a task-log amount must delete its entry rather than save zero. A discarded patch triggers a clean server snapshot so local history returns to its canonical value. Other rejected changes continue to appear in the synchronization panel for review.

New quantitative routines are created by attaching a number or duration tracker to a Tracking task; Duration, Daily Total, and Step Counter are retained only for migrated history. A single target tracker keeps the former task-card and Quick log presentation, including progress and actions, while its values remain tracker entries. The task form groups the **Trackers to log** choices under **How I felt** and **Things I did**. Outside Quick log, every Tracking task card lists its attached trackers, including when only one tracker is attached. Paused trackers are greyed out, display a pause icon, and cannot be logged. Tracker rows remain compact without inline action buttons; selecting a duration tracker opens its **Log amount** and **Log time** choices in an action sheet, and **Log amount** opens the shared number pad directly. The full Tracking task card exposes Lock in numbers or Unlock numbers for a manually logged target; logging, timer, and synchronization actions belong to its tracker rows. Tracking tasks may enable **Quick log**; program tasks cannot. Each unlocked Tracking shortcut offers **Log entry**, alongside **Lock in numbers** when it has a manually logged target. When exactly one tracker is assigned, that action opens its logger directly; otherwise, it opens a sheet of every assigned tracker with its icon and color. Selecting a number or duration tracker opens the shared number pad directly; other tracker types open their appropriate logger. Holding and dragging a shortcut reorders quick logs independently from the full task schedule, updates the local order immediately, and continuously scrolls the shortcut row while the shortcut is held near either horizontal edge.

Completed interval and flashcard sessions reconcile their attributed program-step requirement only when its effective completion state changes. Repeated local refreshes preserve the original completion instead of creating another occurrence update.

Task occurrence updates remain optimistic while progress reloads are running. A completed program-step requirement that is marked incomplete stays incomplete after persistence finishes: older progress responses cannot replace it, and historical session reconciliation respects its recorded incomplete state.

Opening a completed program-step requirement from either its task card or the program runner's requirement list shows a bottom-sheet **Mark incomplete** action instead of changing it immediately. The action resets only the selected check, workout, interval, or flashcard requirement while preserving its session history. Resetting a workout also makes its attached Interval available to start again, even when the workout is reopened from the Interval completion handoff. Opening the completed step card outside its requirements offers **Undone** for the whole dated task while preserving individual requirements. Quantity requirements continue to derive completion from their logged amounts, which can be adjusted through the amount logger.

Programs with **Review if unfinished** enabled expose every unresolved step from earlier days in the retained task history under **Resolve open work**, including steps before a repeating-program cycle boundary. Strict programs provide the same backlog even when **Review if unfinished** is disabled. Every item offers a positive completion action labeled for its task type, such as **Done**, **Lock in numbers**, or **Complete**. Each program item also shows its task icon and color alongside its scheduled date and can be marked missed or used to shift the program; programs cannot be carried forward. Shifting preserves the program's schedule through the unresolved step and delays only the days that follow it. Empty pending occurrences displaced by that shift do not create duplicate program-step cards; logged work remains visible. Any resolution that removes an open item collapses its row immediately; resolving one item removes only that dated occurrence while the remaining backlog stays available.

Open-work review is unavailable while viewing a future date. Future selections never expose review actions for tasks scheduled on or before that selected date.

When **Resolve open work** contains more than three items, it also offers confirmed bulk actions to mark the full backlog missed, carry eligible non-program work forward, or shift every affected program once for each of its unresolved steps. Each bulk action updates offline state and queues one command in a single local transaction; the server applies the complete command atomically so it cannot persist only part of the selection.

Task cards for missed, skipped, and shifted occurrences remain available in their dated history but use the same muted grayscale treatment as other inactive work. The **Missed** and **Shifted** labels retain their semantic colors so the resolution remains clear. Opening a missed or shifted task offers an undo action. Undoing a missed task returns it to pending; undoing a shifted program step also restores the following program schedule by one day. For dates earlier than yesterday, the task action sheet offers separate choices to undo only that day or also reset all later missed and shifted states for that task while preserving completed work and logs. Either undo choice updates its occurrences and program start date optimistically and queues one atomic transaction command.

Resolved or partially logged program occurrences anchor their historical date. If later program shifts would recalculate a different virtual step onto that same date, the Tasks view keeps the stored historical step instead of showing both cards. Carried non-program work can still appear beside the day's scheduled step.

Pending and missed program-step requirements remain actionable on previous dates. Check and quantity requirements update that historical occurrence directly, while interval and Review set requirements start a session attributed to the selected program step and date. Future requirements remain unavailable.

## Health Connect

A number tracker can use **Health Connect steps** as its source. When attached as a task target, it retains the former Step Counter card, syncing state, and optional additional-value logging while storing daily values in tracker entries. Health Connect does not expose screen-time or app-usage records, so Screen time is not offered as an automatically populated Duration tracker. Supporting device screen time would require a separate Android `UsageStatsManager` integration and usage-access permission.
